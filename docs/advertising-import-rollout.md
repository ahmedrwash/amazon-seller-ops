# Advertising import rollout — 25 October 2026

Route: `/ops-hub/advertising`, sidebar Marketing → Advertising. The existing seven-section dashboard links to it from Advertising.

The generated migration installs the canonical `amazon_ads` schema, private original-file storage and an authenticated RPC. No existing sales/PPC facts are copied or overwritten. Legacy product-level metrics continue to show their existing sources; new country/campaign totals are separate until native advertised-product/listing mappings are verified. They must not be added together.

Supported uploads: English-column native CSV/TSV and the supplied curated LARTIA CSV ZIP / XLSX layout. Workbook parsing uses cached values and never executes formulas. ZIP expansion is bounded. Source cells are rendered as escaped text. Original artifacts are private; database rows preserve every supplied column and source row. Account and actor are checked on the server, normalized fields and status from the browser are ignored. The logical hash is computed from source rows on the server, not accepted from the client. Exact/equivalent artifact uploads return the existing batch. The physical file hash is browser-computed provenance, not an Amazon authenticity signature; reviewers must compare the private original with the report settings.

Only reviewed native SP daily campaign totals can currently publish facts. Publishing requires exact dates, native IDs, country/currency, a report generated timestamp, valid IANA timezone, attribution definition/window, sales definition, explicit scope, confirmation and a meaningful review note. Duplicate campaign/date and known breakdown dimensions block publication. Missing base metrics do not become zero. Publication and audit events are transactional and retries do not duplicate data.

Staged report contracts can be corrected using the report settings form and saved from Source review with a review note. Rows are revalidated on the server; original cells are immutable. Saving and approving compare the contract that the reviewer actually saw, rejecting stale concurrent changes. Applied reports cannot be edited this way; corrections require a new source revision.

Curated target/search snapshots, plans and negatives are staged with issues. No bid, budget, campaign or negative-target mutation is sent to Amazon. Incomplete rows are not published by pretending their identity/period is known. Native targeting, search-term, product, placement and bulk uploads are retained for mapping review; automatic publication adapters for these families remain future work pending representative original reports.

Security: private core with RLS; authenticated SELECT only on tables; private-schema SECURITY DEFINER command function has fixed search_path and checks active app/module access and account membership on every request. The public wrapper is SECURITY INVOKER, callable by authenticated users only. Only app admins initialize accounts, granting themselves membership. No service-role credential in the frontend. Editor/admin membership plus upload permission is required for uploads, review, source file downloads and apply. Viewers can read account summaries/results, not raw rows. Module revocation is honored by RPC. Source files referenced by a batch cannot be deleted by client cleanup policies.

Testing: `npm test` runs file parser and real PostgreSQL/PGlite integration tests with Supabase auth/storage stubs, including RLS, cross-account denial, module overrides, deduplication, missing currency/date/metric contracts, breakdown rejection and atomic apply/retry. `npm run lint`, production dependency audit and production build are also required. Test fixtures are synthetic; real advertising records must not enter Git.

Account integration: `legal_entity_ref` and listing references use verified existing public FKs. Global parent/country campaign identity stays separate. A country report without a global parent ID creates a provisional parent source key, never a fabricated global native ID. API profile/entity metadata can be supplied later. Reporting timezone is from the report contract, not user locale.

Operational limits: history returns the latest 100 batches; source review paginates 100 rows; the campaign result table is capped at 1,000 rows and shows no overall aggregate. Attribution maturity and completeness are visible; elapsed attribution window does not guarantee final billing. Expected-campaign coverage is unknown without configuration/report reconciliation. Historical native copies are not automatically backfilled from curated aggregates.
